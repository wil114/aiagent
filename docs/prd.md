# 需求文档

## 1. 应用概述

### 1.1 应用名称
AI+珠宝行业出海战略雷达系统

### 1.2 应用描述
一个面向珠宝集团的战略辅助系统，通过多Agent协作架构自动采集、分析全球珠宝市场信息，每日生成结构化战略简报，帮助管理层快速了解「昨天全球珠宝市场发生了什么、对我们意味着什么、建议看什么」。覆盖中国、日本、韩国、东南亚、美国五大市场，支持多语言处理与跨市场机会识别。集成百度文心大模型（ERNIE 4.5 Turbo）与百度AI搜索接口，支持实时情报分析与流式输出。支持飞书/钉钉Webhook推送战略简报。行动建议按「总部决策-区域管理-门店执行」三级架构分类派发。

---

## 2. 用户与使用场景

### 2.1 目标用户
- 集团总部管理层：需要每日快速了解全球珠宝市场动态，制定战略决策
- 区域管理团队：需要深度洞察区域市场变化，调整区域策略
- 门店负责人：需要了解本地市场趋势，优化门店运营
- 供应链团队：需要监控原材料价格、政策变化、供应商动态
- 非技术背景决策者：需要用人话理解市场变化与行动建议

### 2.2 核心使用场景
- 每日早晨查看自动生成的珠宝行业战略简报，3分钟内掌握关键信息
- 通过可视化界面快速定位高优先级事件
- 点击原始URL追溯信息来源
- 对AI生成结论进行人工复核与反馈
- 通过移动端或飞书/钉钉机器人接收推送
- 输入关注话题触发AI分析，实时查看流式分析结果
- 查阅历史AI分析记录
- 查看业务价值量化指标，评估系统ROI
- 在熔断状态下一键接管人工审核
- 对不准确的AI分析结果触发回滚与重新分析
- 通过路演演示模式向评委/投资人展示系统价值

## 4. 业务规则与逻辑

### 4.1 多Agent协作流程

1. **Scout Agent（侦察兵）**：每日定时采集珠宝行业公开信息（竞品动态、产品趋势、平台政策、社交媒体、法规变化），调用百度AI搜索接口对特定市场关键词进行实时信息采集
2. **Parser Agent（解析员）**：对采集信息进行多语言处理、实体识别、变化检测
3. **Analyst Agent（分析师）**：调用百度文心大模型（ERNIE 4.5 Turbo）执行影响评估、跨市场对比、趋势预测
4. **Briefing Agent（简报员）**：生成结构化日报、优先级排序、行动建议（总部-区域-门店三级）
5. **Validator Agent（校验员）**：执行幻觉检测、多源交叉验证、置信度评分，对LLM生成内容进行二次校验
6. **Human Agent（人工接管）**：对标记事件进行复核反馈、一键确认/质疑

### 4.2 三层雷达分析模型

**L1 信号层**
- 原始信息采集，记录信息来源、采集时间、原始内容
- 关注领域：竞品动态、产品趋势、平台政策、社交媒体、法规变化

**L2 洞察层**
- 识别「什么变了」：对比历史数据，检测新增/变化信息
- 识别「和谁比变了」：跨市场对比，识别差异点
- 识别「变化速度多快」：计算变化频率与趋势

**L3 决策层**
- 跨市场机会时差雷达：当美国出现新趋势时，自动评估日本/中国是否处于「滞后窗口期」
- 生成机会/风险评估与行动建议（总部-区域-门店三级）

### 4.3 每日战略简报结构

每日战略简报必须严格包含以下三部分：

**1. 关键变化要点**
- 按五大维度分类展示：
  + 竞争动态：竞品新品发布、门店扩张、营销活动
  + 产品趋势：材质偏好、设计风格、价格带变化
  + 平台政策：电商平台规则、直播政策、佣金调整
  + 社交媒体：消费者讨论热点、KOL推荐、舆情变化
  + 法规变化：进出口政策、税收调整、质量标准
- 每条变化包含：市场标签、置信度标识、信息来源

**2. 业务潜在影响**
- 机会识别：
  + 市场空白：某市场尚未出现的产品/服务
  + 趋势红利：新兴趋势带来的增长机会
  + 政策利好：政策变化带来的成本优势/市场准入
- 风险预警：
  + 竞争加剧：竞品动作可能带来的市场份额损失
  + 政策风险：法规变化可能带来的合规成本/业务限制
  + 趋势逆转：消费者偏好变化可能带来的库存风险
- 每条影响包含：影响程度（高/中/低）、时间窗口、预期收益/损失

**3. 建议行动（总部-区域-门店三级）**
- 总部决策层：
  + 战略调整：产品线规划、市场进入/退出、并购决策
  + 供应链优化：原材料采购、供应商调整、库存策略
  + 政策应对：合规准备、政府关系、行业协会沟通
- 区域管理层：
  + 区域策略调整：营销活动优化、渠道拓展、价格策略
  + 库存调配：区域间库存调拨、滞销品处理、新品引入
  + 团队培训：销售话术更新、产品知识培训、服务标准优化
- 门店执行层：
  + 陈列调整：橱窗设计、产品组合、促销位布置
  + 促销活动：折扣方案、赠品选择、会员活动
  + 客户沟通：话术更新、异议处理、售后服务
- 每条建议包含：执行层级、优先级、预期效果、执行时间

### 4.4 风控安全机制

**多源印证锁**
- 同一事件需≥2个独立信源确认才可标记为已确认
- 单一信源事件标记为推测或传闻

**多源评分算法**
- 根据信源数量、可信度、一致性计算综合置信度分数
- 置信度分数范围：0-100分
- 评分规则：信源数量×30% + 可信度×40% + 一致性×30%

**分级降级**
- 完整版：包含所有事件与详细分析
- 精简版：仅包含高优先级事件与核心建议
- 应急版：仅包含紧急事件与必要信息

**置信度分层**
- 已确认：≥2个独立信源，通过幻觉检测
- 推测：单一信源或部分验证通过
- 传闻：未验证或存在矛盾信息

**真实熔断器（Circuit Breaker）**
- 触发条件：单日错误率≥20%
- 触发后行为：
  + 系统自动切换到人工审核模式
  + 所有新生成事件需经人工复核后才可发布
  + 首页顶部显示红色提示条「系统已触发熔断，当前为人工审核模式」
  + 置信度仪表盘显示熔断状态与触发原因
  + 人工复核页面显示「一键接管」按钮
- 恢复条件：错误率降至10%以下，且人工确认系统恢复正常
- 历史记录：记录每次熔断的触发时间、持续时长、恢复时间

**降级策略（Degradation）**
- API超时场景：
  + 当百度文心大模型或百度AI搜索接口调用超时时
  + 系统返回上次缓存结果
  + 在结果中显示「降级内容」标签
  + 标注降级原因与缓存时间
- 幻觉检测触发场景：
  + 当Validator Agent检测到幻觉内容时
  + 自动降低该事件置信度评分
  + 添加警告标签「AI生成内容存在不确定性」
  + 标记为待人工复核
  + 记录到风控日志

**回滚机制**
- 用户可对任意AI分析结果标注「不准确」
- 填写不准确原因后，系统触发重新分析
- 重新分析时：
  + 调用百度AI搜索接口重新采集信息
  + 调用百度文心大模型重新生成分析
  + 生成新版本分析结果
- 版本管理：
  + 所有历史版本保留在版本历史中
  + 每个版本包含：生成时间、分析内容、置信度评分、标注状态
  + 用户可查看任意历史版本

**幻觉检测与拦截**
- Validator Agent对LLM生成内容执行幻觉检测
- 检测到幻觉内容时自动拦截，标记为待人工复核
- 记录完整推理链到风控日志

### 4.5 多市场与多语言处理

- 覆盖中国、日本、韩国、东南亚、美国五大市场
- Parser Agent处理多语言内容（中文、日文、韩文、英文等）
- 自动识别时区差异，统一转换为北京时间展示
- 识别多文化语境差异，避免误判

### 4.6 AI分析流程

1. 用户在AI分析页面输入关注话题
2. 系统调用百度AI搜索接口采集相关信息
3. 调用百度文心大模型（ERNIE 4.5 Turbo）进行分析，支持流式输出
4. 实时展示分析结果到页面
5. 分析完成后自动保存到数据库（ai_analyses表）
6. 用户可在历史分析记录列表查阅
7. 用户可对分析结果标注「不准确」并触发回滚

### 4.7 简报推送规则

**飞书Webhook推送**
- 推送格式：富文本卡片
- 推送内容：今日概览、Top3关键事件（含置信度）、行动建议（总部-区域-门店三级）
- 推送时间：系统设置中配置的推送时间
- 推送记录保存到push_logs表

**钉钉Webhook推送**
- 推送格式：Markdown格式
- 推送内容：今日概览、Top3关键事件（含置信度）、行动建议（总部-区域-门店三级）
- 推送时间：系统设置中配置的推送时间
- 推送记录保存到push_logs表

**推送失败处理**
- 记录失败日志到push_logs表
- 用户可在Web端查看简报
- 系统设置页显示最近一次推送状态

### 4.8 跨市场信号传导预测规则

- 当美国市场出现新趋势时，系统自动评估日本/中国市场是否处于「滞后窗口期」
- 预测逻辑：
  + 识别美国市场的关键变化事件
  + 查询历史数据，分析该类变化在日本/中国市场的出现时间差
  + 计算平均时间差（通常为3-6个月）
  + 生成预测：「日本市场可能在X个月后出现类似变化」
- 预测结果展示在业务价值看板中
- 预测准确性通过实际验证结果计算
- 示例：日本轻奢珠宝趋势→预测中国市场4个月后出现类似趋势→实际验证准确

### 4.9 业务价值量化规则

**时间节省计算**
- 人工调研平均耗时：基于历史数据或行业标准设定（如4小时/次）
- 系统生成简报耗时：固定为3分钟
- 累计节省时间 = （4小时 - 3分钟）× 简报生成次数

**机会/风险发现统计**
- 统计系统标记为「机会」或「风险」的事件数量
- 按市场分类统计
- 展示Top3高价值机会与Top3高风险预警
- 示例：美国培育钻石市场增长机会、东南亚电商平台政策风险、日本消费者偏好变化机会

**早期预警成功案例记录**
- 当系统提前预警的事件实际发生时，记录为成功案例
- 计算提前天数 = 实际发生时间 - 预警时间
- 估算避免损失或获得收益（需人工输入）
- 示例：提前30天预警美国培育钻石政策变化，调整产品线避免库存损失

### 4.10 路演演示模式规则

- 路演演示引导页提供5步故事线导航
- 每一步展示关键信息与可视化图表
- 支持一键切换到下一步
- 提供「退出演示模式」按钮，返回正常使用界面
- 演示模式下使用模拟数据，不影响实际系统运行

## 5. 异常与边界情况

| 场景 | 处理方式 |
|------|----------|
| 采集失败（网络异常、信源不可用） | Scout Agent记录失败日志，跳过该信源，不影响其他信源采集 |
| 多语言解析失败 | Parser Agent标记为「解析失败」，转入人工复核队列 |
| 无法获取≥2个独立信源 | 事件标记为推测或传闻，降低优先级 |
| 幻觉检测触发 | Validator Agent拦截该内容，标记为待人工复核，记录推理链到风控日志，自动降低置信度并添加警告标签 |
| 单日错误率≥20% | 自动触发熔断器，切换人工审核模式，所有事件需人工复核后发布，首页显示红色提示条，人工复核页面显示「一键接管」按钮 |
| 无新增事件 | 简报显示「昨日无重大变化」，保持简报生成频率 |
| 移动端推送失败 | 记录失败日志到push_logs表，用户可在Web端查看简报 |
| 飞书/钉钉Webhook推送失败 | 记录失败日志到push_logs表，用户可在Web端查看简报，系统设置页显示推送失败状态 |
| 用户未及时复核 | 系统保留待复核事件，不影响新简报生成 |
| 百度文心大模型API调用失败 | 记录失败日志，AI分析页面显示「分析失败，请稍后重试」 |
| 百度AI搜索接口调用失败 | 记录失败日志，跳过该信源，不影响其他信源采集 |
| AI分析流式输出中断 | 保存已生成内容，标记为「分析未完成」 |
| Webhook URL配置错误 | 测试推送时显示「推送失败，请检查URL配置」 |
| 百度文心大模型API超时 | 触发降级策略，返回上次缓存结果，显示「降级内容」标签与缓存时间，记录到风控日志 |
| 百度AI搜索接口超时 | 触发降级策略，返回上次缓存结果，显示「降级内容」标签与缓存时间，记录到风控日志 |
| 用户标注分析结果为不准确 | 触发回滚机制，重新调用百度AI搜索与百度文心大模型生成新版本，保留历史版本到版本历史 |
| 熔断器触发后错误率未降低 | 持续保持人工审核模式，直到错误率降至10%以下且人工确认恢复 |
| 跨市场信号传导预测失败 | 记录预测失败案例，用于优化预测模型，不影响其他功能 |

11. 用户在风控日志页面查看Validator Agent的校验记录、推理链、幻觉检测结果、降级事件记录、历史错误统计
